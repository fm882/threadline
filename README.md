# Time-aware research agent

This repository is an in-progress implementation of [the PRD](PRD.md) and [the phased plan](plans/time-aware-research-agent.md). Phase 1 currently supports a local HTTP chat backend. The browser interface and later research and recall phases are not complete.

## Local development

Requirements: Node.js 22 or newer, npm, and a running OpenAI-compatible inference gateway with the configured model alias. The tested local gateway uses LiteLLM and AWS Bedrock; [gateway setup](infra/litellm/README.md) explains its separate prerequisites, credentials, and usage charges. Keep provider credentials in the gateway, not the browser.

1. Run `npm install`.
2. Copy `.env.example` to `.env` if you need to change the defaults. Do not commit `.env`.
3. Start the gateway as documented in the gateway README.
4. In another terminal run `npm run dev`. The API listens on `127.0.0.1:3000` and the Vite server on `127.0.0.1:5173`; both stop with the launcher. The Vite server is ready for the browser interface, which is not yet implemented.
5. Check `http://127.0.0.1:5173/health/ready` for gateway configuration and reachability. Liveness is available at `/health/live` and does not require the gateway.

The application uses a server-controlled single local identity and stores local data under `.data/`. The default gateway key is read on the server from `.data/litellm.key`, generated by the gateway launcher. For a remote HTTPS gateway, set `INFERENCE_BASE_URL` and an explicit `INFERENCE_API_KEY`; the local master key is never sent to a remote host. The configured chat model must match `config/model-capabilities.json`.

## Verification

Run `npm test` and `npm run typecheck`. Tests use local persistence and synthetic external responses. [Phase 1 verification](docs/PHASE1_VERIFICATION.md) distinguishes those tests from the bounded live checks. `node scripts/verify-chat.mjs` requires the running gateway and sends one synthetic model request that can incur a provider charge.

The application is designed for local single-user development; it is not a hosted multi-user deployment. Check the plan for remaining acceptance criteria before treating a phase as complete.
