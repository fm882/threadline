# Phase 10 context budget implementation

The local capability manifest supplies the context ceiling. Main chat reserves up to 8,192 output tokens within a 64,000-token context; the Nova Micro fallback reserves up to 4,096 output tokens within a 56,000-token context. Both use a 2,048-unit safety allowance. The prompt compiler measures serialized UTF-8 payload size, adds message framing, and counts schemas/tool definitions and evidence payloads. This is a conservative tokenizer-independent proxy, not a tokenizer count; no per-model tokenizer has been configured.

When a prompt exceeds its envelope, the compiler removes only the oldest complete user/assistant exchanges. It retains system instructions, historical source context, and the current user request. Research calls recompile both the tool-call request and the continuation containing the tool result; the tool result, assistant tool call, structured-output instructions, and tool schema remain in the measured payload. An oversized required prompt becomes a visible limitation; content is not silently truncated. The configured smaller-context fallback remains available after a retryable main-route failure; no summary or repair calls are issued.

The same research run signal and outer deadline bound model invocations and search. A run can use bounded follow-up search rounds (at most two follow-up rounds), while sharing a maximum of four model requests, two searches, and 128,000 serialized prompt bytes across all subjects and rounds. It does not start independent per-subject jobs. Validation requires one result or explicit gap per requested subject. Traces record compaction cost, removed exchange count, and history coverage without source text.

`tests/context-budget.test.ts` exercises 1,000 distracting exchanges, preservation of the required subject list and current question, schema overhead, complete tool-call/result retention, and visible overflow. `tests/history-context.test.ts` verifies that an oversized original is not sent to the model and produces a visible limitation. `tests/tracing.test.ts` verifies the redacted budget and coverage decision metadata.

The fallback path is enabled in the checked-in manifest only after compatibility attestations for the exact `BEDROCK_FAST_ROUTE`, smaller context ceiling, streaming, tool calls, and prompted JSON. Readiness also requires the gateway to advertise both aliases. When the main call fails with a retryable transport, 408, 429, or 5xx error, the client recompiles the exact messages/tool payload against the fallback envelope before reserving and invoking that route. Failed attempts and both prompt sizes count against the same run budget. Abort, context overflow, and ordinary 4xx/capability errors do not trigger fallback. The accepted fallback is then used for the remainder of that research run.

`tests/capabilities.test.ts` rejects missing or incompatible fallback assumptions; `tests/readiness.test.ts` requires the configured fallback alias to be advertised; and `tests/research-client.test.ts` verifies one route switch, smaller-budget recompilation with current-question retention, shared budget accounting, no retry for an unsupported request, and no fallback invocation when the preserved current question cannot fit. The route-switch tests use a local mock and do not attest provider compatibility.

The checked-in manifest permits `chat-fast-v1` as a smaller-context fallback after live verification of the exact LiteLLM route. Fast streaming and the two-call research contract passed against `bedrock/converse/us.amazon.nova-micro-v1:0` on 2026-11-16; the route check and usage are recorded in [inference verification](INFERENCE_VERIFICATION.md). The actual `researchClient` path also passed with a locally simulated main-route 503 and synthetic search evidence: both fallback calls went to the configured Bedrock route, the result passed the application's strict schema and citation checks, and usage stayed within the shared budget. Nova Micro emitted wrapper tags and initially produced an unsupported comparison in a current-only turn; the application strips only recognized wrappers before strict validation and now shows an empty comparison example when no historical basis exists. The separate Phase 12 live assignment batch completed against the Token Harbor main route; details and quality limits are in [the live evaluation report](PHASE12_LIVE_EVALUATION.md). Model-tokenizer accuracy, retrieval quality under large histories, and measured hosted concurrency remain unestablished; synthetic load evidence is in the Phase 12 report.
